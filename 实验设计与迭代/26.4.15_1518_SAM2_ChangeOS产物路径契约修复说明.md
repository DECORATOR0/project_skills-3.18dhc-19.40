# 26.4.15  SAM2 / ChangeOS 产物路径契约修复说明

## 背景

这次修复针对的是 `SAM2` 和 `ChangeOS` 这两类产物文件型感知工具。

此前的行为有两个明显问题：

- `model_results.csv` 命中后只返回路径字符串，调用成功时没有保证 `output_path` 对应文件真实存在。
- 同一份产物同时出现 `benchmark/model_out/...`、`benchmark/out/question...`、`benchmark/out/earth-bench-c-...`、`benchmark/out/benchmark/...` 等多套历史路径，下游工具缺少稳定映射。

这会让 executor 遇到一种环境性断链：

- 上游工具名义上成功
- 下游需要读文件时却拿不到可消费产物

## 这次修复的目标

- 保证 `SAM2` / `ChangeOS` 成功返回时，`output_path` 对应文件已经 materialize 到本次 runtime 的 `TEMP_DIR`。
- 保留历史路径兼容，让旧轨迹里常见的几套路径都能解析到同一份真实文件。
- 不给 executor 额外补推理能力。找不到真实产物时直接失败。

## 代码改动

### 1. `agent/tools/Perception.py`

新增了三层逻辑：

- 离线产物查找候选集
  - 优先尝试 `model_results.csv` 里的返回路径
  - 再尝试 `output_path` 在 workspace 中的同名路径
  - 再按题号尝试几套显式历史目录：
    - `benchmark/model_out/question{qid}/...`
    - `benchmark/out/question{qid}/...`
    - `benchmark/out/earth-bench-c-{qid}/...`
    - `benchmark/out/benchmark/data/question{qid}/...`
    - `benchmark/out/benchmark/out/question{qid}/...`

- 产物 materialize
  - 命中真实文件后，复制到本次调用的 `TEMP_DIR / output_path`
  - 复制完成后做可读性校验
  - 成功时统一返回 `Result save at <TEMP_DIR/...>`

- alias 注册
  - 把 `model_results.csv` 返回路径、调用时的 `output_path`、materialize 后的 canonical 路径，以及显式历史候选路径，一并写入运行时 alias registry

### 2. `nlrl_skills/tools.py`

补了运行时 alias registry：

- `ToolContext` 增加 `artifact_alias_registry`
- `EOToolRuntime` 在加载 EO 工具模块时，通过环境变量把 registry 路径传给工具层
- `Toolbox._resolve_temp_artifact_path()` 在原有解析逻辑前，先查询 alias registry

这样下游工具读路径时，能够稳定命中：

- `benchmark/model_out/...`
- `benchmark/out/question...`
- `benchmark/out/earth-bench-c-...`
- 本次 run 里的 `TEMP_DIR / output_path`

## 设计边界

这次修复刻意保持了较硬的边界：

- 只有显式路径映射会被接受
- 没有加入全盘模糊搜索或跨题号猜测
- 找不到真实源文件时，`SAM2` / `ChangeOS` 会直接失败

这个边界能避免把 executor 的真实能力抬高。

## 对 executor 的影响

- executor 继续按原有工具契约工作
- 成功时拿到的路径已经可消费
- 环境负责兑现产物句柄
- 真实产物缺失时，runtime 会给出硬失败，executor 需要自行 fallback

## 当前结论

- 这次改动把 `SAM2` / `ChangeOS` 从“返回路径字符串”推进到了“返回可读产物句柄”
- 历史路径兼容也被收到了 runtime 内部
- 这部分修复针对的是环境断链，不会替 executor 做额外推理
