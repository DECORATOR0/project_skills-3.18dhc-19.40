# 2026-04-03 到 2026-04-06 `6` 到 `7.7` 阶段实验脉络

注：文件名里的 `2359` 是为了在 `03_实验记录` 中按分钟级时间前缀稳定排序，不表示某一次真实 run 的开始时间。

## 1. 这篇文档的职责

这篇的目标是给当前整理版补一个很关键的口径，不去把 `6 ~ 7.7` 全部重写一遍：

- `8` 之前的材料仍然算数
- 只是它们所处的测试框架和当前 `v8` 不完全同口径

所以这篇要回答的是：

1. `6 ~ 7.7` 里哪些东西今天仍然有效
2. 哪些数字可以当“历史基线”看
3. 哪些内容不能直接和 `v8 formal60` 并表

---

## 2. 先把总判断说死

当前总判断可以直接写成：

- `8` 之前的很多实验、思考、流程图、错误分型、收口结论仍然有效
- `8` 之后的主线在评测框架、skill contract、聚合形态和 budget 口径上更严谨，所以不能把前后的分数直接混成一张表

换句话说：

- `6 ~ 7.7` 更像“把主线形态探索出来的前史”
- `8+` 更像“在新 contract 下开始做严格收口的正式主线”

---

## 3. 为什么不能简单把前后分数直接并表

`6 ~ 7.7` 和当前 `v8` 至少有四类关键差异：

### 3.1 skill contract 不同

`7` 之前主线里，很多实验仍然建立在：

- `family`
- 题目级 `shortlist`
- 旧的 family 聚合与消费口径

而 `v8` 已经改成：

- 去 family 先验
- `allowed-tools` 做 executor 硬边界
- `flat/tree` 双形态共享同一聚类结果

### 3.2 聚合方式不同

`7` 之前大量实验是：

- 先按 family 分桶
- 再 family 内聚合

而 `v8` 是：

- retained skill 先自动聚类
- 再基于同一份 cluster assignment 分别生成 `flat/tree`

### 3.3 executor memory 口径不同

`7` 之前的很多结论是在旧 memory / 旧执行包装口径下形成的。

而当前主线已经进入：

- token-budget executor
- 明确的 `executor_total_token_budget`

因此前后 executor 的真实承载条件不同。

### 3.4 对照框架更完整

`8` 之后，当前主线已经比较明确地形成了以下对照组：

- `flat`
- `tree`
- `no-skill / all-tools`
- `Earth-Agent origin`

这让后期解释结果时比 `7` 之前更稳。

## 4. 但 `6 ~ 7.7` 里哪些东西仍然非常有价值

### 4.1 `6`：定下了消费侧正确形态

旧文档 `7.4.1` 已经把这一点说得很清楚：

- 在当时的 `6-skill` 对比里，`direct-executor` 明显优于拆分式后半段

旧文档给出的对照分数是：

- `direct-executor = 44.76`
- 拆分式后半段 = `35.08`

这条结论今天仍然有效，因为它解决的是“系统形态”问题，能够跨 run 复用，不依赖某次偶然波动。

当前仍可继承的结论：

- 训练侧应该尽量产出与单 executor 消费方式一致的 skill
- 不要再轻易回到更复杂的多段 handoff 架构

### 4.2 `7.1`：task-local 单 skill 训练线已经真正打通

`7.1` 的意义不在分数，而在流程：

- `sample-task-set`
- `train-task-local-parallel`
- `aggregate-task-local-skills`

这些链路真正接通了。

它今天仍然有价值，因为它证明：

- 当前主线在 `8` 之前已经有训练-聚合闭环
- `8` 是在前面闭环跑通之后，继续把 contract 和评测方式收紧

### 4.3 `7.2`：第一组正式可引用的小规模闭环基线

旧文档给出的 `7.2` 口径是：

- `60` 题并行训练
- 只取成功样本
- 聚成 `6` 个 family skill
- 回测同一批 `60` 题

基线结果：

- 训练：`31 / 60 = 0.5167`
- 聚合后测试：`18 / 60 = 0.3000`

这组数字今天不该和 `v8 formal60` 直接并表，但它仍然有效地说明了：

- 问题不只是聚合掉分
- 训练侧本身也没有自然训强

### 4.4 `7.3`：错误分型和工程优先级判断仍然有价值

旧文档 `7.3` 做了两件今天仍然重要的事：

1. 把失败分成：
   - 结构化输出失败
   - 尾部中断
   - 系统能力 / 执行能力问题
2. 明确指出：
   - executor 上下文会持续膨胀
   - 只靠补 JSON mode 解决不了这个问题

这类错误分型与优先级判断，今天仍然有效，因为它们属于：

- failure taxonomy
- 工程排障顺序

这些判断依赖的是 failure taxonomy 和工程排障顺序，不依赖某个旧 benchmark score。

### 4.5 `7.3.5`：第一版全量主线沉淀

旧文档里给出的 `7.3.5` 当前认可结果是：

- 总题数 `248`
- 已完成 `140`
- 成功且保留 `107`
- 完成题口径准确率 `107 / 140 = 0.7643`
- 基于这 `107` 个 task-local source skill 聚合后，补测结果为 `59 / 140 = 0.4214`

这组结果今天仍然有价值，因为它回答的是：

- 在大规模口径下，这条线第一次真正沉淀出了什么

虽然它不等于 `v8`，但它仍然是当前 repo 里非常重要的一段前史。

### 4.6 `7.5`：成本替代实验和 same140 基线仍然重要

旧文档里，`7.5` 已经完成了：

- `SSSAI gpt-5.2` 训练侧替代
- same `140` 题训练
- 聚合
- same `140` 测试

旧文档给出的正式口径是：

- 训练：`94 / 140 = 0.6714`
- 测试：`62 / 140 = 0.4429`

这组结果今天仍然有价值，因为它解决的是：

- 成本替代是否还能保住主线效果

这个问题在 `v8` 之前就已经出现。

### 4.7 `7.7`：no-skill 但保 shortlist 的消融仍然重要

旧文档里 `7.7` 的正式结果是：

- `no-skill-executor`，但仍保留 question-level shortlist
- same `140` 题结果：`56 / 140 = 0.4000`

它相对 `7.5` 的结论可以直接写成：

- shortlist 本身有帮助
- 但拿掉 aggregated skill 与 skill routing 后，整体仍然退化

这条消融思路本身，今天依然是有效的比较框架。

## 6. 当前不建议怎么用

### 6.1 不要把 `6 ~ 7.7` 的 score 和 `v8 formal60` 直接拼成一张排行榜

因为底层假设已经变了：

- family 与非 family
- shortlist 与无 shortlist
- old executor 与 token-budget executor
- single aggregated family line 与 `flat/tree`

### 6.2 不要把 `8` 理解成对前面探索的否定

更准确的理解应当是：

- `8` 站在 `6 ~ 7.7` 的结果之上，把主线重新收口

所以前面的材料应该被继承，继续作为有效历史使用。
