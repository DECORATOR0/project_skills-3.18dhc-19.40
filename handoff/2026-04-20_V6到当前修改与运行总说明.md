# V6 到当前修改与运行总说明

## 1. 这份文档是给谁看的

这份文档面向接手 `V6 prompt snapshot` 这条线的人，重点只说三件事：

- 从原始 `V6` 到当前版本，大方向上做过哪些修正。
- 当前结果应该怎么理解。
- 如果现在要继续跑 `30` 题两轮训练、`no-skill` 基线、`strict gold replay`，分别怎么启动。

当前建议对齐的代码基线：

- 分支：`batch_method-xsy-26.4.11`
- 当前提交：`c0a78db`
- 仓库根目录：`/data/xsy/project_skills-3.18dhc-19.40`

## 2. 一句话概括当前状态

当前这条线已经不是“原始 V6 prompt 直接重跑”，它是一个带了多轮本地修补的演化版，修正主要落在四层：

1. 提示词和执行框架
2. 工具和 runtime
3. 数据和 gold
4. 对照评测和诊断脚本

所以后面再看分数，最稳妥的理解方式是：这是 `V6` 的本地增强版，目标已经从“复现原始 V6”推进到了“让训练链路更可信、让问题更容易定位”。

## 3. 这段时间大概做了哪些修正

### 3.1 提示词 / 执行框架层

这一层的核心变化是把原始 `V6` 接进当前的单 skill batch RL 框架，并把执行约束收紧。

大方向上的修正有这些：

- 把 `V6 prompt snapshot` 接到本地训练链路里
- 固定成 `phase-based single skill`
- 用 `strict-state` 接管 phase 跳转
- 只允许在 `CONCLUDE` 阶段输出最终答案
- actor / critic 的输入结构做过调整，skill 修改更偏局部修补，不再是粗放重写

这一层带来的直接影响是：

- 当前 skill 更像“分阶段执行规范”
- 当前分数更接近真实能力
- 和原始 V6 的 prompt 行为已经拉开了明显差距

### 3.2 工具 / runtime 层

这一层做的是把“环境问题”尽量从 executor 身上摘出去。

大方向上的修正有这些：

- 补 batch 工具接口和 `benchmark/out` bridge
- 修感知工具 lookup，减少离线结果明明存在却命不中的情况
- 收紧 runtime 的 success 判定，避免语义上已经失败的调用继续被算成成功
- 修 `SAM2` / `ChangeOS` 这类输出型工具的产物路径契约
- 给历史路径加 alias 映射，减少下游读不到产物的问题

这一层带来的直接影响是：

- 一批原来卡在路径和契约上的题会更稳定
- 一批原来“假成功”的题会被更早暴露出来
- 当前分数里混入的 runtime 噪声比早期少很多

### 3.3 数据 / gold 层

这一层做的是把 benchmark 本身的脏点往前收口。

大方向上的修正有这些：

- 对 `248` 题做过系统扫查
- 补了一批 `gold overrides`
- 落了 `dataalignv1`
- 让题面、数据目录、gold answer、gold trajectory 的关系更对齐

当前推荐基线已经切到：

- `benchmark/question_dataalign_v1.json`
- `data/converted/earth_bench_skill_rl/question_dataalign_v1.json`
- `data/gold_overrides/earth_bench_skill_rl/full248_v1.json`

这一层带来的直接影响是：

- 当前训练和评测看到的数据，已经不是原始 `question.json` 那一版
- 现在的结果更能反映 skill / runtime 问题，数据脏点的干扰有所下降

### 3.4 对照评测 / 诊断层

这一层做的是把“问题到底落在哪”拆得更清楚。

当前已经补上的对照和诊断能力有这些：

- `strict-state` 逐题复盘文档生成
- `strict gold replay`
- `no-skill baseline`
- handoff 用的 PPT 生成脚本

这一层的意义很直接：

- 如果训练结果有波动，可以更快判断问题落在 skill、runtime，还是 benchmark 本身

## 4. 当前结果大概应该怎么理解

当前这条线的几个关键数字可以这样记：

- 早期 V6 本地重跑大约在 `14/30`
- 那一版里有不少脆弱成功
- 约束收紧、工具修补、数据对齐之后，长期大约在 `17-18/30`
- `strict gold replay` 目前大约是 `1/30`
- `GPT-5.2 no-skill` 对照大约在 `14/30`

这组数字说明两件事：

- 当前版本比原始 V6 更接近真实能力上限
- `Earth Bench` 本身仍然带着比较重的 benchmark 噪声，尤其是脏 gold、旧路径依赖和历史轨迹失效

## 6. 如果现在要继续跑，直接用这些命令

下面这些命令默认面向这台机器。换机器时，需要先补齐同名 config、本地 benchmark 数据和对应环境。

### 6.1 重跑 30 题两轮训练

```bash
cd /data/xsy/project_skills-3.18dhc-19.40

export RUN_NAME=20260420_train_batch30_v6prompt_jh_gpt54_c10_bridge_goldfix248_dataalignv1
export CONCURRENCY=10
export CONFIG_PATH=/data/xsy/project_skills-3.18dhc-19.40/configs/system-train-xsy-gpt54-jh-v6-promptsnapshot-goldfix248-dataalignv1.json
export BOOTSTRAP_SNAPSHOT=/data/xsy/project_skills-3.18dhc-19.40/tmp/v6_bootstrap_snapshot

nohup bash /data/xsy/project_skills-3.18dhc-19.40/scripts/run_train_batch30_v6_with_bridge.sh \
  > "/data/xsy/project_skills-3.18dhc-19.40/runs/_launch_logs/${RUN_NAME}.log" 2>&1 < /dev/null &
```

补充说明：

- 默认任务文件就是 `data/task_sets/default_batch/train_all_30.txt`
- 默认是两轮训练
- 这个脚本内部会自动起 bridge，同步 `benchmark/out`

### 6.2 跑 no-skill baseline

```bash
cd /data/xsy/project_skills-3.18dhc-19.40
python3 scripts/run_no_skill_batch_eval.py \
  --config /data/xsy/project_skills-3.18dhc-19.40/configs/system-train-xsy-gpt54-jh-v6-promptsnapshot-goldfix248-dataalignv1.json \
  --question-file /data/xsy/project_skills-3.18dhc-19.40/data/task_sets/default_batch/train_all_30.txt \
  --concurrency 10 \
  --run-name no_skill_batch30_dataalignv1
```

### 6.3 跑 strict gold replay

```bash
cd /data/xsy/project_skills-3.18dhc-19.40

  --config /data/xsy/project_skills-3.18dhc-19.40/configs/system-train-xsy-gpt54-jh-v6-promptsnapshot-goldfix248-dataalignv1.json \
```

## 7. 我建议接手的人先做什么

如果目标是把当前线快速接起来，我建议按这个顺序：

1. 先重跑一次 `30` 题两轮训练
2. 再跑一次 `strict gold replay`
3. 再跑一次 `no-skill baseline`
4. 用这三条结果一起判断问题落点

这样做的好处很直接：

- 能先确认当前训练链是否稳定
- 能先确认 gold 轨迹是不是已经大面积失效
- 能先确认 skill 本身到底有没有带来增益
